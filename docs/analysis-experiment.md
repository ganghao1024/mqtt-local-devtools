# 完整 Topic 字段表最小实验

运行 `node tests/serve-panel.js` 后，打开 http://127.0.0.1:8174/tests/analysis-panel.html?experiment=matrix 。此地址展示实际故障分析页面，仅通信输入使用模拟数据，不连接 Broker，也不发送 MQTT 消息。

页面自动选择 `demo/site/device/A`，N 为 5，关注字段为 `status, data.battery`。同一父分组下还有 B Topic 的两条交错消息。

实验确认的功能已应用于正式工具：高级设置已移除，直接按“完整 Topic 对应一个设备”自动比较并高亮变化，不需要配置 Payload 设备字段或确认对象。不同来源页、连接、收发方向仍分别比较。实验页仅额外加载模拟数据和实验提示，分析行为与正式工具一致。

1. 看默认表格：必须有 5 行，最新在前，依次为 null / 字段不存在、running / 79、running / 80、idle / 80、idle / 80。未变化行不省略，变化单元格有文字标记。切换逐条变化时也应最新在前，前后值保持旧值 → 新值。
2. 点击“显示全部字段”，再点“分析”：除 status 和 battery 外还应出现 device、diagnostics.code。后者从捕获序号第 3 条消息才出现，表格最下面两行显示字段不存在。字段变化规律按最近变化排序，状态流转保持捕获先后顺序。
3. 切换到 B，点击“分析”：只显示 B 的 2 行，明确提示不足 5 条，不补入 A。
4. 回到 A，将 N 改为 3 后分析：只显示 A 的最后 3 条，不出现最初的 idle。
5. 点击某行“查看原文”，核对状态和电量。可点击“一起导出”，JSON 中应有完整 Topic 配置、5 条字段表行和对应的 5 条原始消息（N 为 5 时）。
6. 初次开始分析后界面显示“本轮已冻结”，分析缓存不再自动收录新消息。点击“获取最新 N 条”才主动复制当前 Topic 的最新一轮并分析，完成后继续冻结。缓存中的旧消息保留；获取失败不改变当前轮次。此实验的消息输入固定，可通过重置恢复，动态新消息与多轮取样另由 analysis-freeze.browser.js 自动验证。

实验通过标准：无需在消息清单和详情之间反复跳转，就能指出状态首次变化的消息和电量首次下降的消息；能够按需增加字段，明确分辨 null 与缺失。

顶部“重置实验”恢复初始数据与设置。正式使用需重新加载扩展并打开 MQTT 面板；实验数据不会注入真实面板。
