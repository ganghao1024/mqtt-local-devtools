# MQTT Local DevTools 界面规范

本规范对应 v0.8.6 的界面设计。以 `816c88f` 时的 `panel.css`、`panel.html`、`analysis-ui.js` 和 `popup.html` 为起点，沿用原生 HTML/CSS/JavaScript、深色主题和工作台布局，并与当前脉冲图标统一。不是第三方品牌规范，也没有新增组件库或字体下载。

## 来源与设计决策

| 类别 | 处理方式 |
| --- | --- |
| 已提取 | 保留 `--bg`、`--surface`、`--text`、`--muted`、`--blue`、`--green`、`--mono` 等已有名称；沿用系统中文字体和 Consolas 等宽字体栈。 |
| 已调整 | 背景沿用图标的深色底，提亮次要文字；主按钮和交互强调色统一为当前图标的蓝青色，绿色用于接收、连接和成功状态。 |
| 已新增 | 主操作、控件边界、焦点、提示背景、字号、间距、圆角、尺寸与动效的语义 tokens；模块键盘导航与窄窗口换行规则。 |
| 复用资产 | 直接引用项目 `icons/icon*.png`，从当前 `icons/icon.svg` 提取底色 `#0b1018` 和脉冲线色 `#22d3ee`。界面样式不生成或转换图标。 |
| 未提供 | 浅色主题、外部品牌字体、移动应用组件及设计编辑器文件；本次没有向外部设计工具上传。 |

主要颜色的原值和新值如下。这是有意的界面优化，不是对旧色板的无损导出。

| Token | 原值 | 当前值 / 用途 |
| --- | --- | --- |
| `--bg` | `#0d1117` | `#0b1018`，工作区底色 |
| `--surface` | `#161b22` | `#131c28`，工具栏、导航与面板 |
| `--muted` | `#8b949e` | `#a1b1c7`，说明和次要标签 |
| `--brand` | 无 | `#22d3ee`，来自图标的脉冲线；用于主按钮、焦点与品牌强调 |
| `--blue-bright` | `#58a6ff` | 引用 `--brand-hover: #67e8f9`，用于选中标签、链接和悬停 |
| 主按钮 | `#238636` | `--action` 引用 `--brand`，配 `--bg` 深色文字 |
| 控件边界 | 常复用分隔线颜色 | `--control-border: #557b88`，区分输入框和背景 |

`--brand-subtle: #102b34` 用于轻量提示底色，`--surface-selected: #12303a` 用于选中行。`--blue` 和 `--blue-bright` 保留旧名称作为品牌色的兼容别名，新增样式可直接使用 `--brand`。图标蓝青色上配深色文字；不直接配白字，以保持小字号按钮的对比度。

## 单一来源与接入

`design-tokens.css` 是主题与通用尺寸的唯一来源。`panel.html` 先加载它，再加载 `panel.css`；`popup.html` 同样先加载 tokens，再加载 `popup.css`。测试页面也读取相同文件。保留旧变量名让现有模块继续消费这些规则，不新增构建或生成步骤。

```html
<link rel="stylesheet" href="design-tokens.css">
<link rel="stylesheet" href="panel.css">
```

新界面优先复用 `.action-button`、`.text-button`、`.search-field`、`.editor-tab` 和现有状态类。局部样式引用语义变量，不复制整份色板。打包扩展时必须包含 `design-tokens.css` 和 `popup.css`，并保留所有现有运行时资源。

## 基础规则

- 文字：UI 基准 13px，主要标签 14px，模块标题 18px；新增说明、表格和 Payload 使用 12px。原 MQTT 时间等紧凑诊断信息保留已有密度。系统字体取决于用户操作系统，项目没有嵌入字体文件。
- 间距：`--space-1` 至 `--space-6` 分别为 4、8、12、16、20、24px。常用控件间距 8px，参数区间距 12px，面板内边距 12–16px。
- 控件：标准高度 36px，紧凑操作 30px；边框使用 `--control-border`，普通分隔线使用 `--border` / `--border-soft`，不把装饰分隔线当作输入框边界。
- 圆角：小控件 6px，面板和主要按钮 8px；12px 预留给较大的容器。菜单使用 `--shadow-menu`，常规数据面板不加大阴影。
- 动效：仅颜色与边框使用 140ms 过渡；尊重 `prefers-reduced-motion`。高频消息不添加逐行入场动画。

## 组件与状态

| 组件 | 使用规则 |
| --- | --- |
| 模块导航 | MQTT、HTTP、故障分析使用同一层级的标签。选中项配深蓝青色底与浅蓝青色文字；只有当前项进入 Tab 序列。方向键循环切换，Home / End 跳到首末项并保留导航焦点。 |
| 主按钮 | `.action-button.primary` 用于“分析”“发送”和 MQTT 导出。蓝青色底配深色文字，悬停变亮，禁用降低透明度；焦点保留外描边。 |
| 次要操作 | 普通 `.action-button` 带边框；局部操作用 `.text-button`。清空独立缓存使用红色文字，放在“更多操作”中。 |
| 输入和筛选 | 原生 label 与可访问名称。MQTT 筛选栏可换行，搜索框保持可见，不以横向滚动隐藏主要筛选。 |
| 接收 / 发送 | 接收使用绿色文字和底色，发送沿用蓝青色；同时保留“接收 / 发送”文字。颜色不作为唯一依据。 |
| 分析冻结 | 蓝青色提示保留“本轮已冻结”、略过条数和“获取最新 N 条”入口说明；主操作仍叫“分析”。 |
| 字段变化 | 黄色值、左侧标记与“新增 / 删除 / 修改”文字一起出现；悬停仍保留变化底色。缺失字段保留独立文字。 |
| 容量与错误 | 容量提示使用黄色文字与背景，错误使用红色，并保留具体原因；不靠颜色推断失败。 |
| 数据表格 | 字段表保持最新在前、固定表头与消息列，宽内容在表格内部滚动。MQTT 原列表行高保留 46px，与虚拟列表一致。 |
| HTTP 工作区 | 三段边界清晰，保留原有上下分隔条和高度记忆；状态、控件与导航复用公共 tokens。 |
| 扩展弹窗 | 同一主题、状态框、两步使用提示和清晰更新入口；固定宽度 340px。 |

## 窗口与滚动

目标是桌面 DevTools，可见宽度优先验证 1440、1280、900 和 640px。沿用原有 MQTT 三栏和断点行为：900px 及以下隐藏详情栏，680px 及以下隐藏侧栏；表格继续内部横向滚动。模块导航在较窄窗口隐藏品牌文字以留出操作空间。

故障分析在 760px 及以下让参数分行，并给结果卡保留高度，通过工作区纵向滚动查看余下内容；不通过删除消息行来适配宽度。HTTP 保留现有最小工作宽度与拖动布局。这不等同于完整手机端适配。

## 验证与维护

`npm run check` 包含 tokens 别名完整性和循环检查、消费者资源路径检查、图标源文件与品牌色一致性、关键文字配对 4.5:1 及焦点 / 控件边界 3:1 检查。`npm run test:browser` 包含真实面板的计算样式、模块键盘导航、筛选换行、三种窗口宽度、虚拟行高、HTTP 分隔条、减少动效与弹窗验证。

新增 token 时写清语义及允许的背景配对；调整公共尺寸时核对虚拟列表和分隔条的实际几何尺寸。颜色测试覆盖的是本规范中的配对和代表性页面元素，不是完整无障碍认证。真实 Broker、浏览器原生弹窗宿主和长时间性能仍需实际环境验证。
