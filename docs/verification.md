## 高频与字节验证

先分析最初 100 条并冻结，再输入 12000 条消息：MQTT 原列表淘汰旧记录，分析缓存仍只有最初 100 条，原摘要、原文和导出保留。在每 20 ms 输入 20 条的标称 1000 条/秒流量期间完成原列表筛选、滚动、详情搜索，并通过“获取最新 N 条”复制新的 1000 条进行分析；原 100 条不删除。原列表 DOM 行数小于 80，变化列表每页最多 100 行。

手动清空后另输入 180 条约 200 KB 的 Payload，最终保留最初 167 条，约 31.9 / 32 MiB，剩余 13 条不收录。下载原文验证第一条仍为 load-20000，最后一条为 load-20166，后续小消息也不会继续覆盖或追加。手动清空选择不释放缓存；手动清空缓存后新消息成功入库。捕获通道断开后缓存与可导出的结果仍保留。

独立缓存最多 5000 条 / 32 MiB，分析选择最多 1000 个 ID，报告最多 8 MiB。字段表最多 100 列 / 20000 单元格 / 4 MiB，显式指定超限字段拒绝，自动收集字段超限标记不完整；单元测试验证上限。逐条变化最多 10000 项，字段汇总最多 2000 项，状态流转预览最多 16 个，长值预览最多 512 字符，导出最多 64 MiB。所有分析仅按用户操作执行，字段收集、行生成和连续比较按每 20 条让出界面线程。

实际下载产物位于 Git 忽略目录：.playwright-cli/analysis-changes.json、analysis-raw.json、analysis-combined.json，完整 Topic 导出 analysis-topic-*.json，字段表合并导出 analysis-matrix-combined.json，新一轮导出 analysis-refreshed-combined.json。字段表截图 analysis-matrix-focused.png，窄窗口截图 analysis-matrix-900.png，冻结截图 analysis-frozen.png，手动获取截图 analysis-manual-refresh.png。
